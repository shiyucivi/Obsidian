### 1 自定义实现`FromRequest`
`FromRequest trait`和`FromRequestParts trait`是所有提取器类型的核心trait。两个trait的区别在于前者会消耗掉请求的body而后者不会。因此后者可以支持对一个请求使用多个提取器。
`Json`、`FormData`、`String` / `Bytes`均属于前者，其余提取器属于后者。
如果想实现一个自定义提取器，需要定义一个结构体并实现`FromRequest`或`FromRequestParts` trait。然后在handler中，将handler的参数类型定为该结构体。
```rust
// 自定义Json提取器
use axum::{
	extract::{rejection::JsonRejection, FromRequest, MatchedPath, Request},
	http::StatusCode,
	response::IntoResponse,
	RequestPartsExt,
};
use serde_json::{json, Value};

pub struct Json<T>(T);

// 泛型S代表状态State的类型，通常不需要处理
impl <S, T> FromRequest<S> for Json<T>
where S: Send + Sync, T: Axum::Json<T>: FromRequest<S, Rejection = JsonRejection>
{
	// Rejection类型必须满足IntoReponse
	type Rejection = (StatusCode, axum::Json<Value>)
	async fn from_request(req: Request,state: &S) -> Result<Self, Self::Rejection>{
		// 将request分割为parts和body
		let (mut parts, body) = req.into_parts();
		// 提取path
		let path = parts.extract::<MatchedPath>().await
			.map(|path| path.as_str().to_string())
			.ok();
		// 重新组装为request
		let req = Request::from_parts(parts, body);
		// 提取Json
		match axum::Json::<T>::from_request(req, state).await {
			// 封装为自己的Json类型
			Ok(value) => {Ok(Self(value.0))},
			Error(rejection) => {
				let payload = json!({
				//json宏可以将一个字面量Json构造为Value
					"message": rejection.body_text(),
					"origin": "custom_extractor",
					"path": path,
				});
				Err((rejection.status(), axum::Json(payload)))
			}
		}
	}
}
```
这里使用的`serde_json::Value`是一个枚举，用于表示动态的Json类型，这个枚举没有实现`IntoResponse`不能直接放入响应中，需要使用`axum::Json`包装。
```rust
pub enum Value { 
	Null, // 对应 JSON 的 null 
	Bool(bool), // 对应 true 或 false 
	Number(Number), // 对应整数或浮点数 (内部有更细的区分) 
	String(String), // 对应 JSON 字符串 
	Array(Vec<Value>), // 对应 JSON 数组 [...] 
	Object(Map<String, Value>), // 对应 JSON 对象 {...} 
}
```

在handler中使用：
```rust
fn handler(Json(payload): Json<Payload>) {
	dgb!(payload);
}
```

### 2 派生宏定义提取器
使用`#[derive(FromRequest)]`可以为一个类型自动实现`FromRequest` trait。要求所有字段实现了`FromRequest`。同时需要通过`via`指定提取器，通过rejection指定提取失败的响应的类型。
```rust
#[derive(FromRequest)]
#[from_request(via(axum::Json), rejection(axum::http::StatusCode))]
struct Json<T>(T)
```
#### 2.1 rejection
指定的rejection类型必须满足两个条件：
- 实现`IntoResponse`
- 实现`From<Rejection>`，这里的`Rejection`来自于`axum`中的提取器的`Rejection`类型。也就是说任何字段的提取失败类型必须能够转化为宏中指定的`Rejection`类型。
如果不指定rejection类型，那么会使用默认的提取器中的`Rejection`。
```rust
use axum::{
	extract::rejection::JsonRejection,
	extract::FromRequest,
	http::StatusCode,
	response::IntoResponse,
};
use serde_json::{json, Value};

#[derive(FromRequest)]
#[from_request(via(axum::Json), rejection(ExtractError))]
struct Json<T>(T)

#[derive(Debug)]
pub struct ExtractError {
	code: StatusCode,
	message: String
}
impl IntoResponse for ExtractError {
	fn into_response(self) -> axum::response::Response {
		(self.code, self.message).into_response()
	}
}
impl From<JsonRejection> for ExtractError {
	fn from(value: JsonRejection) -> Self {
		Self {
			code: value.status(),
			message: value.body_text()
		}
	}
}
fn handler(Json(value): Json<Value>) {
	//todo
}
```
#### 2.2 组合多个提取器
派生宏的强大之处是可以为一个类型组合多个提取器。可以不使用`via`指定提取器类型而是指定每个字段的提取器类型：
```rust
use axum::{
	extract::rejection::JsonRejection,
	extract::FromRequest,
	http::StatusCode,
	response::IntoResponse,
};
use serde::{Serialize, Deserialize}
use serde_json::{json, Value};
#[derive(FromRequest)]
#[from_request(rejection(ExtractError))]
pub struct UserExtractor {
	user_id: Path<UserId>,
	payload: Json<UserInfo>
}
#[derive(Debug, Deserialize)]
struct UserId {
	id: i32,
}
#[derive(Debug, Deserialize)]
struct UserInfo {
	username: String, 
	email: String,
}
impl From<PathRejection> for ExtractError {
	fn from(value: PathRejection) -> Self {
		Self { 
			code: value.status(), 
			message: value.body_text() 
		}
	}
}
async fn user_handler(request: UserExtractor) -> String {
	let UserExtractor { user_id, user_info } = request;
	format!( "ID: {}, Username: {}, Email: {}", user_id.id, user_info.username, user_info.email)    
}
```
