### 1 为部分接口设置中间件
中间件的设置非常灵活，既可以针对整个服务设置中间件，也可以针对某个接口单独设置中间件，还可以根据接口的方法和参数设置中间件。
```rust
use axum::{
    extract::{DefaultBodyLimit},
    routing::{delete, get},
    Router,
};
use tower_http::{
    compression::CompressionLayer,
    limit::RequestBodyLimitLayer,
};
Router::new()
	.route(
		"/app",
		// 为接口的get设置压缩中间件
		get(get_handler.layer(CompressionLayer::new()))
			// 为接口的post设置请求体积限制中间件
			.post_service(
				post_handler
					.layer((
						DefaultBodyLimit::disable(),
						RequestBodyLimitLayer::new(1024 * 5_000 /* ~5mb */),
					))
			),
	)
	.layer(
		// 组合式中间件
		ServiceBuilder::new()
			// 错误转换
			.layer(HandleErrorLayer::new(handle_error))
			// 日志span
			.layer(TraceLayer::new_for_http())
			// 最大连接数
			.concurrency_limit(1024)
			// 超时, 超时中间件必须设置错误转换中间件
			.timeout(Duration::from_secs(60))
	)

	.with_state(Arc::clone(&state));
```
### 2 错误处理层`HandleErrorLayer`
某些中间件用于处理异常情况，如最大连接限制、超时等。这些中间件本身带有默认的错误响应机制。例如`TimeoutLayer` 超时时会返回 `tower::timeout::error::Elapsed`错误，而`ConcurrencyLimitLayer`会在连接池耗尽时返回`tower::load_shed::error::Overloaded`。当同时出现这些错误类型时服务器无法确定返回的错误类型。这需要我们将这些错误类型同一放进一个分支条件中进行匹配和判断：
```rust
use tower::{BoxError, ServiceBuilder};
async fn handler_error(error: BoxError) -> impl IntoResponse {
	// 超时错误
    if error.is::<tower::timeout::error::Elapsed>() {
        return (StatusCode::REQUEST_TIMEOUT, Cow::from("request timed out"));
    }
    // 请求体超过限制
    if error.is::<tower::load_shed::error::Overloaded>() {
        return (StatusCode::BAD_REQUEST, Cow::from("Service is overloaded, try later"));
    }
    // 其他错误
    (
        StatusCode::INTERNAL_SERVER_ERROR,
        Cow::from(format!("Unhandled internal error: {error}")),
    )
}
```
