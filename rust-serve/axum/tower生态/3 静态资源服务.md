构建静态资源服务非常简单，主要依赖于 `tower_http` crate 提供的 `ServeDir`和 `ServeFile` 中间件。需要开启`tower_http`的`fs`feature。
### 1 基础的静态文件服务
 `ServeDir` 可以快速创建一个文件服务器的`Service`，使用`nest_service`挂在到路由上即可。
 ```rust
use axum::Router;
use tower_http::{
    services::{ServeDir},
    trace::TraceLayer,
};

#[tokio::main]
async fn main() {
	// 1. 创建 ServeDir 实例，指向 "assets" 目录 // 如果目录不存在，程序会在启动时 panic，生产环境建议先检查目录是否存在 
	let serve_dir = ServeDir::new("assets");
	// 2. 构建路由 
	// 方式 A: 将静态资源挂载到 /static 路径下 
	// 访问 http://localhost:3000/static/index.html -> 对应 assets/index.html 
	let app = Router::new() .nest_service("/static", serve_dir);
	
	let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
	axum::serve(listener, app.layer(TraceLayer::new_for_http())).await;
}
 ```
 `nest` 和 `nest_service` 的区别在于**它们接收的参数类型不同**
 - **`nest`**: 用于嵌套另一个 **`Router`**。
- **`nest_service`**: 用于嵌套任何实现了 **`Service`** trait 的对象。
### 2 静态资源服务配置
```rust
use tower_http::{
	services::{ServeDir, ServeFile}
}
// 使用assets目录创建静态文件服务，并放在/static路由下
Router::new().nest_service("/static", ServeDir::new("assets"))

// 当文件未找到，设置一个默认的失败响应资源而不是404
let server_dir = ServeDir::new("assets")
	.not_found_service(ServeFile::new("assets/index.html"));
Router::new()
	.nest_service("/static", server_dir.clone())
	.fallback_service(server_dir)
	
async fn handle_404() -> (StatusCode, &'static str) {
	(StatusCode::NOT_FOUND, "Not found")
}
// 将一个handler转为Service
let service = handle_404.into_service();
let server_dir = ServeDir::new("assets")
	.not_found_service(service);
Router::new()
	.nest_service("/static", server_dir.clone())
	.fallback_service(server_dir)
```
