### 1 视图
可以利用某个查询语句创建一个视图，视图可以当作表来进行查询使用。
```sql
create view myview as
	select name, temp_lo, temp_hi, date, location
	from weather w , cities c
	where w.city = c.name;
```
这会在当前模式中创建一个名为`myview`的视图。（同一模式中的视图不能重名）
```sql
-- 使用视图进行查询
select name, location from myview;
```
视图的优势在于：
- 统一的可复用的查询逻辑接口
- 实现业务与物理表的隔离，底层表的修改只需修改视图无需修改相关语句
- 只暴露部分字段避免敏感字段泄露
### 2 主键与外键
创建表时，可以将某个列当作主键，主键具有唯一性和不可变性：
```sql
create table cities (
	name varchar(80) primary key,
	location point
);
```
可以为一个表指定一个外键列，所有插入这个表的数据，其外键列的值必须与指定外键表的对应列相匹配。例如`cities`表中不存在`name`为`Hollywood`的数据，向`weather`表插入行时如果其外键列`city`如果为`Hollywood`会插入失败。这被称为“数据的引用完整性”。
```sql
create table weahter (
	city varchar(80) references cities (name),
	temp_lo int,
	temp_hi int,
	prcp real,
	date date
);
```
### 3 事务
事务就是将多个操作语句封装为一个完整的原子操作，要么都完成，要么都不完成。
```sql
-- Alice给Bob转账100.00元
begin; -- 开始事务
-- 将Alice的账户余额减少100
update accounts set balance = balance - 100.00 where name = 'Alice'
-- 找到Alice的支行名称
-- 将支行的账户余额减少100
update branches set balance = balance - 100.00 where 
	name = (Select branch_name from accounts where name = 'Alice')
-- 将Bob的账户和支行的余额增加100
update accounts set balance = balance + 100.00 where name = 'Bob'
update branches set balance = balance + 100.00 where 
	name = (select branche_name from accounts where name = 'Bob')
commit; -- 没有报错，事务完成
rollback; -- 存在报错，回滚所有操作并清除事务
```
注意，在一个数据库连接中，一个事务要么完成`COMMIT`要么失败清除`ROLLBACK`。事务中无法执行其他任何操作。
如果事务中语句执行出现错误，必须`ROLLBACK`，如果不的话数据库连接就会进入死锁状态，无法执行任何sql语句。
#### 3.1 保存点
在使用`SAVEPOINT`定义一个保存点后，可以在必要时利用`ROLLBACK TO`回滚到该保存点。
该事务中位于保存点和回滚点之间的数据库修改都会被放弃，但是早于该保存点的修改则会被保存。
```sql
begin;
update accounts set balance = balance - 100.00 where name = 'Alice';
savepoint my_savepoint;
update accounts set balance = balance + 100.00 where name = 'Bob';
rollback to my_savepoint;
-- 如果Alice给Bob转账失败，转账给Wally
update accounts set balance = balance + 100.00 where name = 'Wally';
commit;
```
### 4 窗口函数
窗口函数也用于在在表的行中进行计算。但是窗口函数不像聚合函数输出单独的行，而是会保留原始的行。
**==窗口函数的含义就是，在对于每一行将它分区到一个行集（也就是窗口帧）中，再单独对每个窗口中的所有行执行函数==**

窗口函数的基本语法：
```sql
function_name(column_name) OVER (
    [PARTITION BY partition_expression, ...]
    [ORDER BY sort_expression [ASC | DESC], ...]
    [frame_clause]
)
```
- `function_name`是窗口函数名，如`SUM() AVG()`等。
- `OVER`子句决定了这是一个窗口函数而不是普通函数，决定了哪些行被分离出来由窗口函数处理
- `PARTITION BY`将行进行分组，类似于`GROUP BY`，但是不合并行。如果没有这个子句就是将表中的所有行视为一整个窗口
- `ORDER BY`对输出行进行排序
- `frame_clause`：窗口帧子句，进一步限定窗口范围
```sql
-- 列出weather表中每个城市的最高气温和每个城市的平均最高气温
select city, temp_hi, avg(temp_hi) over (partition by city) from weather w;
```
#### 4.1 窗口排序 
可以在`OVER`后面使用`ORDER BY`来控制窗口函数处理行的顺序：
```sql
-- 列出城市和最高温度，并按照每个城市的最高温度从小到大排序
select city, temp_hi, rank() over (partition by city order by temp_hi) from weather w;
```
注意，使用`ORDER BY`时对窗口内的行进行排序时，一些窗口函数只作用于窗口帧里的从排序后第一个行到当前行以及与当前行在`ORDER BY`排序条件相等的行，不包括后续的行。例如：
```sql
-- 计算所有雇员的薪水
select salary, sum(salary) over () from employee;
```
结果：
```
 salary |  sum
   5200 | 18700
   5000 | 18700
   5000 | 18700
   3500 | 18700
```
如果加上`ORDER BY`：
```sql
select salary sum(salary) over (order by salary) from employee; 
```
结果为：
```
 salary |  sum
   3500 | 3500
   5000 | 13500
   5000 | 13500
   5200 | 18700
```
这里的合计是从第一个（最低的）薪水一直到当前行，包括任何与当前行的x薪水相同的行。
#### 4.2 窗口子查询
窗口函数只允许出现在查询的`SELECT`列表和`ORDER BY`子句中，不能出现在`GROUP BY`、`HAVING`和`WHERE`子句中。因为窗口函数的执行在这些子句之后。
如果想在窗口执行后再进行分组或者过滤，可以使用子查询：
```sql
-- 查询出最高温度大于城市评价最高温度的行
select city, temp_hi
from
	(select city, temp_hi, avg(temp_hi) over (partition by city) from weather)
where temp_hi > avg;
```
### 5 继承
假如我们想创建具有集合关系的两个表：一个首都capitals表和一个城市cities表。可以先创建父表cities表，再使用`INHERTS`子句从父表继承一个子表capitals。
```sql
create table cities {
	name text,
	population real,
	location point,
};
create table capitals {
	country char(3) UNIQUE NOT NULL
} inherts cities;
```
capitals表有一个附加列`country`。
从父表查询时，如果不加限制条件，则默认父表子表一起查询：
```sql
select name, population from cities where population > 500000;
```
如果想只查询父表而不查询子表，要用`ONLY`子句限制：
```sql
select name, population from only cities where population > 500000;
```
