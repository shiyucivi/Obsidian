在一个表中查询一些行时，系统通常会扫描整个表导致查询效率低。对于一些常用的列可以对其开启索引（主键约束会自动创建B-tree索引）。
在一个列上创建索引：
```sql
CREATE INDEX id_index ON table1 (id);
```
创建索引后，在使用`WHERE`或`JOIN`对该列进行查询时，会通过索引结构直接跳转到目标位置，降低时间复杂度。
索引可以极大提升`SELECT`查询以及`JOIN`和排序的效率，但是会增加`INSERT`/`UPDATE`等写入操作的开销。
#### 1 索引类型
#### 1.1 B-tree
B-tree是默认的索引类型，处理可排序数据上的等值和范围查询，支持需要比较操作符进行查询的列(`<` 、`>` 、`>=`、`<=`、`=`、`BETWEEN`、`IN`)。
B-tree索引也可以用于检索排序数据。
#### 1.2 Hash
Hash索引是由一个索引列计算出的32位哈希值。Hash通常只支持于等值比较(`=`)。
#### 1.3 GiST和SP-GiST
GiST是支持多种不同的索引策略的索引框架，适用于几何、全文搜索、数组等非标量类型。
GiST支持的操作符包括：
```
<<   &<   &>   >>   <<|   &<|   |&>   |>>   @>   <@   ~=   &&
```
SP-GiST是GiST的非平衡树版本，二者适用的数据类型相同。
#### 1.4 GIN
GIN索引是倒排索引，适用于包含了多个值的列，例如数组、JSON、全文搜索等。支持的操作符包括：
```
<@   @>   =   &&
```
#### 1.5 BRIN
BRIN索引适用于连续物理区域的表，特别是物理顺序与逻辑顺序一致的表（例如时间序列）。
BRIN索引主要支持比较操作符。
### 2 索引排序
索引可以让数据以指定的顺序排列，使得`ORDER BY`查询时不需要额外的排序运算。
默认B-tree索引将他的项以升序存储，并将空值放在最后。
创建B-tree索引时通过`ASC`、`DESC`、`NULLS FIRST`和`NULLS LAST`选项来改变索引的排序：
```sql
-- NULL放在前列
CREATE INDEX test2_info_nulls_low ON test2 (info NULLS FIRST);
-- 降序排列，NULL放在后面
CREATE INDEX test3_desc_index ON test3 (id DESC NULLS LAST);
```
