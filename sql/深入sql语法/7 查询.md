`SELECT`查询命令的基本格式是：
```sql
[WITH with_queries] SELECT _select_list_ FROM table_name [filter_specification] [sort_specification]
```
### 1 表表达式
表表达式的结果是一个表，这个表达式必须包含一个`FROM`子句，可以选择使用`WHERE`、`GROUP BY`、`HAVING`子句进行筛选或排序。
#### 1.1 `FROM`子句
`FROM`子句从一系列表引用中生成一个虚拟表，表引用可以是一个物理表的名字，也可以是一个`SELECT`子查询、一个`JOIN`连接。这个虚拟表再经过筛选排序子句的转换最后生成一个表表达式结果。
##### 1.1.1 连接表
连接表就是将两个表按连接条件连接起来。常用的连接方式是内连接、外连接和交叉连接
###### 1.1.1.1 交叉连接
```sql
SELECT * FROM A CROSS JOIN B;
-- 等效于
SELECT * FROM A, B;
```
交叉连接是将两个表的所有行都组合一次。如果A表有`M`行，B表有`N`行，那么结果有`M*N`行。交叉连接不需要连接条件。
###### 1.1.1.2 条件连接
条件连接包括内连接（`INNER JOIN`）、外连接`LEFT|RIGHT JOIN`和全外连接`FULL JOIN`。然后使用`ON`或`USING`指定连接条件。
- 内连接是默认的连接方式。两个表连接的行必须完全匹配连接条件，不匹配的行会被忽略。
```sql
SELECT * FROM orders o JOIN products p ON o.product_id = p.id;
```
- 外连接包括左外连接与右外连接。左表的行完全保留，右表可以匹配的行保留，不匹配的填充空值。
```sql
SELECT * FROM orders o LEFT JOIN products p ON o.product_id = p.id;
```
- 全外连接是两个表所有的行都保留并互相匹配，不匹配的填充控制。
```sql
SELECT * FROM orders o FULL JOIN products p ON o.product_id = p.id;
```
`ON`子句是最常用的指定连接条件的子句，可以是任意布尔表达式。
`USING`适用于两个表存在相同连接列名的特殊情况，并且`USING`只支持等值连接：
```sql
SELECT * FROM employees e JOIN leaders l USEING (id);
-- 相当于
SELECT * FROM employees e JOIN leaders l ON e.id = l.id;
```
两种子句中都不能包含`WHERE`子句。
##### 1.1.2 子查询
子查询指定了一个派生表，必须使用括号包裹并指定一个别名
```sql
SELECT c.id * FROM (SELECT * FROM orders WHERE date > '2026-01-01') AS c;
```
##### 1.1.3 表函数
表函数是生成一个行集合的函数。
```sql
CREATE FUNCTION get_employees_by_dept(dept_id INT) 
	REURNS TABLE (
		emp_id INT,
		emp_name TEXT,
	) AS $$
BEGIN
    RETURN QUERY
    SELECT id, name, salary
    FROM employees
    WHERE department_id = dept_id;
END;
$$ LANGUAGE plpgsql;
```
调用方式：
```sql
SELECT * FROM get_employees_by_dept(10);
```
#### 1.2 `WHERE`子句
`FROM`子句生成虚拟表后，需要对虚拟表的每一行进行条件筛选。通常`WHERE`中包含一个布尔表达式。
```sql
SELECT * FROM fdt WHERE c1 BETWEEN 10 AND 100;
SELECT * FROM fdt WHERE c1 IN (SELECT c3 FROM t2 WHERE c2 = fdt.c1 + 10)
```
#### 1.3 `GROUP BY`和`HAVING`分组查询
通过`WHERE`过滤后的行可以使用`GROUP BY`进行分组以及`HAVING`筛选分组。
`GROUP BY`将行按照某一列的值进行分组：
```sql
SELECT product_id, price FROM orders GROUP BY product_id;
SELECT * orders GROUP BY product_id; --❌
```
**`SELECT` 中出现的非聚合列，必须出现在 `GROUP BY` 中**。
```sql
-- 计算每种商品的订单总额
SELECT p.id, p.name, SUM(o.price)
	FROM products p LEFT JOIN orders ON p.id = o.product_id
	GROUP BY p.id, p.name;
```
`HAVING`用于对分组进行筛选，**`HAVING`子句通常只包含聚合列**：
```sql
-- 计算2026年后订单总额大于5000元的每种商品的订单总额
SELECT p.id, p.name, sum(o.price)
	FROM products p LEFT JOIN orders ON p.id = o.product_id
	WHERE p.date > '2026-01-01'
	GROUP BY p.id, p.name
	HAVING sum(o.price) > 5000;
```
#### 1.4 `GROUPING SETS`、`CUBE`和`ROLLUP`
`GROUPING SETS`就是按不同列的组合，对一个表中的数据进行多次分组再组合到一起。`CUBE`和`ROLL UP`是其特殊形式。
假如存在表：
```sql
CREATE TABLE sales (
    region   TEXT,
    product  TEXT,
    amount   NUMERIC
);
```
想同时得到：按每个地区分组的销售总额、按每个产品分组的销售总额、按每个地区每种产品分组的销售总额：
```sql
SELECT region, product, SUM(amount) as total
FROM sales
GROUP BY GROUPING SETS (
	(region),
	(product),
	(region, product)
);	
```
每一个分组中，未参与分组的列会返回`NULL`。例如按产品分组时，`region`列会为`NULL`。
相较于`UNION ALL`数据库只扫描一次，性能更好。
`ROLL UP`和`CUBE`是`GROUPING SETS`的特殊组合形式：
- `ROLLUP(a, b, c)` 等价于 `GROUPING SETS((a,b,c), (a,b), (a), ())`
- `CUBE(a, b)` 等价于 `GROUPING SETS((a,b), (a), (b), ())`
### 2 选择列表
`FROM`子句中的表表达式会构建一个虚拟表，这个虚拟表会被`SELECT`选择列表处理，来判断最终输出的列。
#### 2.1 选择列表项
最简单的选择列表类型是 `*`，它发出表表达式生成的所有列。
通常会使用逗号分隔的列名：
```sql
SELECT tbl1.a, tbl2.a, tbl1.b FROM tbl1, tbl2;
```
使用`AS`可以为输出列指定列名：
```sql
SELECT a from, b + c AS sum FROM ...
```
#### 2.2 `DISTINCT`去重
`SELECT DISTINCT`可以根据列消除存在重复值的行。
`DISTINCT`默认会对传入的所有列进行去重：
```sql
SELECT DISTINCT name, department FROM employees;
```
这会返回`(name, department)`的唯一组合。
PgSQL还提供了`DISTINCT ON`来去重并获取第一条，必须和`ORDER BY`搭配使用。
```sql
SELECT DISTINCT ON (department) id, name, department
FROM employees
ORDER BY department, id;
```
### 3 行排序`ORDER BY`
`ORDER BY`子句指定了输出行的排序顺序。可以指定多个排序表达式：
```sql
SELECT a, b FROM table1 ORDER BY a + b, c;
-- 输出行会优先按照a+b的值排名，当a+b相等时按照c排名
```
每个表达式后面可以使用`ASC`和`DESC`表示升序和降序。默认为`ASC`升序排列，较小的在前。
`NULLS FIRST`和`NULLS LAST`用来决定在排序顺序中，空值是出现在非空值之前还是之后。默认情况下空值被认为比非空值都要大。
### 4 组合查询结果`UNION`|`INTERSECT`|`EXCEPT`
PgSQL提供了`UNION`、`INTERSECT`、`EXCEPT`对两个查询的结果进行交集、并集、差集的组合。组合时不按列名匹配而是按传入的顺序进行组合，两个查询结果的列数必须一致，对应列的数据必须可互相转换。最终输出结果以第一个查询结果的列为准。
```sql
SELECT id, name FROM employees
UNION
SELECT cid, fullname FROM contractors;
```
三种组合都是默认去重的（`DISTINCT`）。如果不去重需要使用`UNION ALL`等进行声明。
如果需要排序或分组，要把排序或分组子句放在组合结果之后，列名与第一个查询的列名一致：
```sql
(SELECT col1, col2 FROM table1)
UNION
(SELECT col1, col2 FROM table2)
ORDER BY col1;
```
### 5 `LIMIT`和`OFFSET`截取
`LIMIT`和`OFFSET`用于截取查询结果的行的一部分。`LIMIT`表示截取数量，`OFFSET`表示截取开始的位置：
```sql
SELECT * FROM table ORDER BY id  LIMIT 10 OFFEST 15;
-- 10到14的数据
```
分页查询（以第一页为例）：
```SQL
SELECT * FROM table ORDER BY create_time LIMIT 10 OFFSET 0;
```
### 6 `WITH`查询
`WITH`提供了一个结果集（公共表表达式 Common Table Expression，CTE）。这个结果集可以被视为一个查询的临时表的定义。相较于子查询，`WITH`查询定义更清晰且支持多次复用。
#### 6.1 `WITH`+`SELECT`构建CTE
`WITH`适用于将复杂的查询分解为多个简单的部分，特别是多次嵌套查询的情况，`WITH`可以通过链式调用清晰地表达多个互相嵌套的查询结果。
例如首先构建一个各地区总订单额的表表达式，在构建一个总订单额高于平均的地区的表表达式。再从这些地区筛选出订单。
```sql
WITH region_orders AS (
	SELECT region, SUM(price) AS total_amount
	FROM orders
	GROUP BY region
), top_regions AS (
	SELECT region
	FROM region_orders
	WHERE total_amount > (SELECT AVG(total_amount) FROM region_orders)
)
SELECT 
	region, 
	product, 
	SUM(quantity) AS product_units, 
	SUM(price) AS product_prders
FROM orders
WHERE region IN (SELECT region FROM top_regions)
GROUP BY region, product;
```
#### 6.2 物化
物化（Materialize）指的是将CTE的查询结果存储到磁盘或内存中，查询时直接读取结果。PgSQL默认不进行物化，优化器会将CTE语句内联到SQL语句中再进行查询。
物化查询会带来一定的性能损失（无法使用索引、分区等优化），但是对于需要多次重复查询且查询消耗大的数据可以选择物化来避免重复查询。
```sql
WITH my_cte AS MATERIALIZED (
    SELECT ... 
)
SELECT ... FROM my_cte ...;
```
