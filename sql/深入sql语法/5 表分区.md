分区指的是将逻辑上的一个大表分成一些小的物理片。用于提升查询性能。特别是表非常大的时候。
PgSQL通常提供了这些分区方法：
范围划分，按照表中某个列或一组列的值的范围划分分区。
列表划分，直接指定每个分区的键值来划分分区。
哈希分区，为每个分区指定模数和余数对表进行分区，分区内的行需要满足分区键的值除以模数等于余数。
### 1 声明式分区
声明分区需要列出分割分区的方法、分区键的列。声明分区的表被称为分区表。分区也可以被定义为分区表进行子分区。
#### 1.1 创建分区表与分区
例如一个订单表：
```sql
CREATE TABLE orders (
	id integer DEFAULT SERIAL,
	date date NOT NULL,
	price numeric NOT NULL,
);
```
大部分时候只需要查询最近一年的数据。这种情况下可以使用按时间范围分区来创建一个分区。
##### 1.1.1 声明分区表
使用`PARTITION BY`子句将orders表声明为分区表，子句包括分区方法（例如`RANGE`）以及用于分区键的列。
```sql
CREATE TABLE orders (
	id integer DEFAULT SERIAL,
	date date NOT NULL,
	price numeric NOT NULL,
) PARTITION BY RANGE (date);
```
##### 1.1.2 创建分区
使用`CREATE TABLE part PARTITION OF table`创建分区。每个分区的定义必须按照分区表的分区方法与分区键定义边界。分区的边界不能存在重叠。
```sql
CREATE TABLE orders_2026 PARTITION OF orders 
	FOR VALUES FROM ('2026-01-01') TO ('2027-01-01');
-- 分区的范围边界是左包含右不包含，因此不会包含2027-01-01日期的订单
INSERT INTO orders (date, price) VALUES 
('2026-03-01', 26.17),
('2026-03-24', 102.1);
-- 自动落入对应分区
```
分区创建完成后，可以直接向分区中插入数据，也可以在分区表中插入数据，系统会自动将对应数据映射到对应分区。
==**分区表的所有分区的集合不必覆盖所有可能的值，但插入分区表的数据必须找到对应的分区，否则会报错。因此分区表的设计原则是你只需要存储所有分区范围内的数据，如果想覆盖所有范围需要创建一个默认分区作为兜底。**==
```sql
-- 创建默认分区
CREATE TABLE orders_default PARTITION OF orders DEFAULT;
```
#### 1.2 维护分区
分区的最大好处就是可以非常快速地移除分区中的旧数据并增加新数据。
如果不需要分区内的数据（比如数据过期），那么可以直接删除分区从而删除所有数据。
```sql
DROP TABLE orders_2026;
```
更常用的方法是把分区从分区表中移除，但保留这个分区作为一个表：
```sql
ALTER TABLE orders DETACH PARTITION order_2026;
```
`DETACH PARTITION`会将分区和数据从主表分离出来变成一个普通的表。之后仍然可以作为一个表来查询。
### 2 分区剪枝
分区剪枝是一种提升声明式分区查询性能的优化方法。例如：
```sql
SELECT count(*) FROM orders WHERE date >= DATE '2026-01-01';
```
如果没有剪枝，那么查询会扫描表中的所有分区。而启用剪枝后会先检查分区定义，然后再看改分区的边界是否复合查询条件，如果不复合则不扫描。
PgSQL的声明式分区默认开启剪枝优化。查询剪枝要生效，必须满足：
- 分区键出现在`WHERE`条件中
- `WHERE`中的条件可被优化器静态分析，一些复杂函数和自定义函数无法剪枝
可以通过`EXPLAIN`语句来检查分区剪枝是否生效：
```sql
EXPLAIN SELECT * FROM orders WHERE date >= DATE '2026-01-01';
```
这会列出所有符合条件的分区。如果列出所有分区那么说明剪枝可能未生效。
