### 1 连接与创建数据库
在命令行中连接数据库：
```shell
psql -U postgres -h localhost
```
`-U`后的参数代表用户名，`-h`后的参数代表主机名称或地址。连接成功后进入sql模式，输入SQL命令执行操作。
创建数据库：
```sql
CREATE DATABASE mydb;
\l
\c mydb
```
这样就创建了一个名为`mydb`的数据库。创建后使用`\l`命令查看该服务下的所有数据库。使用`/c mydb`进入这个数据库中执行sql命令。
在mydb中创建数据库表：
```sql
CREATE TABLE weather (
    city            varchar(80),   -- varchar(80)表示最长存储80个字符的字符串
    temp_lo         int,           -- 整数类型
    temp_hi         int,           -- 整数类型
    prcp            real,          -- 单精度浮点数类型
    date            date           -- 日期date类型
);
```
这个`weather`表默认在`mydb`下的`public`模式中。
==**每个表中的列的顺序通常是固定的，但pg不会保证每次查询的顺序都相同。**==
如果不需要某个表可以删除：
```sql
DROP TABLE weather;
```
### 2 数据表操作
#### 2.1 添加行
`INSERT`语句用于向表中添加行。向`weather`表中快速插入一个数据：
```sql
insert into weather values ('Beijing', 2, 10, 0.25, '2026-03-06');
```
这种方式需要我们准确知道所有列的顺序。可以使用指定列的方法并且可以忽略某些非必要列：
```sql
insert into weather (date, city, temp_hi, temp_lo)
	values ('2026-03-06', 'Tianjin', 4, 15);
```
从文件批量导入数据：
```sql
copy weather FROM '/home/user/weather.csv'; 
```
#### 2.2 查询表
`SELECT FROM table`语句用于从表中检索数据并列出指定列：
```sql
select * from weather; -- *代表所有列
select city, temp_hi, temp_lo from weather; --查询weather表中所有数据的city、temp_hi和temp_lo
```
可以写入列的表达式作为一个新的临时的列（`AS`不是必写的）：
```sql
select city, (temp_hi+temp_lo)/2 as temp_svg, date from weather;
```

`WHERE`字句用于筛选行，后面跟一个布尔表达式，常用的布尔运算符包括`AND`、`OR`和`NOT`：
```sql
select * from weather where city='Beijing' and temp_hi>1; 
--列出city为Beijing且temp_hi大于1的所有行
```

`ORDER BY`字句用于指定返回行的顺序，这个顺序默认从小到大排列：
```sql
select * from weather order by temp_lo, temp_hi;
```
可以用`DISTINCT`来修饰列名，消除拥有相同列值的行，通常与`ORDER BY`搭配来获取某个列的最大值或最小值：
```sql
select distinct city from weather order by city; 
-- 按照数据库默认的排序，对所有city列进行排序并过滤重复值
```
#### 2.3 表连接查询
##### 2.3.1 内连接
一次访问多张表的查询被称为`join`查询。将一个表中的行与另一个表的行按某一列连接进行查询。
```sql
select * from weather join cities on city=name;
-- 将weather表的city列与cities表的name列进行连接，查询连接后的数据
```
如果两个表中存在同名的列，可以指定列名与列名所在的表：
```sql
select weather.city, weather.temp_lo, weather.temp_hi, weather.date, 
	cities.location
	from weather join cities on weather.city=cities.name;
```
还有一种连接语法等价于上面的`join`：
```sql
select * from weather, cities
    where city = name;
```
以上的连接方式被称为内连接，需要被连接的列之间完全匹配（相同列值）。不匹配的行将被忽略。
##### 2.3.2 外连接
外连接需要指定连接的方向。即左连接（`LEFT OUTER JOIN`）或者右连接（`RIGHT OUTER JOIN`），`OUTER`可以省略。
这是一个左连接，**==左表（`JOIN`的左边）的行全部保留，右表的空行填补空值==**
```sql
select * from weather left join cities on weather.city = cities.name;
```
**==如果右表中与左表中的行存在多对一的关系，那么左表也会展开成多个重复行保持一一对应。==**
右连接可以视为左连接的镜像操作。即右表全保留。除了左连接和右连接，还有全外连接，即两边的表全部保留。
实际当中`LEFT JOIN`可以应对大多数的连接查询。
##### 2.3.3 自链接
自连接就是把一个表和自己连接起来。
```sql
SELECT w1.city, w1.temp_lo AS low, w1.temp_hi AS high,
	w2.city, w2.temp_lo AS low, w2.temp_hi AS high
FROM weather w1 JOIN weather w2
	ON w1.temp_lo < w2.temp_lo AND w1.temp_hi > w2.temp_hi;
```
#### 2.4 更新行
可以使用`UPDATE`子句更新现有的行：
```sql
-- 将日期大于1994-01-01的temp_lo列都减一
update weather 
	set temp_lo = temp_lo - 1
	where date > '1994-01-01';
```
#### 2.5 删除行
使用`DELETE`子句删除行：
```sql
delete from weather where city = "Tokyo";
```
#### 2.6 UNION
`UNION`用于将多个`SELECT`查询的结果拼接在一起，常用于将多个不同表的查询数据拼接在一起。
```sql
select name, dept from employees
union [ALL]
select name, dept from contractors;
```
每个`SELECT`所选择的列数必须完全相同，列名可以不同但以第一个`SELECT`为准。查询结果中两个完全相同的行会被去重（可以使用`UNION ALL`保留重复行）。
### 3 聚合函数
聚合函数可以从多个输入行中计算出这些行的聚合数据，通常输出单独的聚合行（除非配合`GROUP BY`等），如计数`count`，平均值`avg`，求和`sum`，最大值`max`，最小值`min`。
```sql
select max(temp_lo) from weather; --取出temp_lo最大的行
```
#### 3.1 聚合函数作为子查询进行筛选
聚合函数通常用于`SELECT`子句中，不能用于`WHERE`子句中（因为`WHERE`子句决定了筛选哪些行作为聚合函数的输入，不能同时既筛选又聚合计算）。
如果想使用聚合函数作为筛选，可以使用==**子查询**==：
```sql
-- 查询出temp_hi最大的行的city列
select city from weather
	where temp_hi = (select max(temp_hi) from weather);

-- 查询出最高气温大于平均最高气温的日期
select date from weather
	where temp_hi > (select avg(temp_hi) from weather);
```
#### 3.2 GROUP BY和HAVING
`GROUP BY` 和 `HAVING` 是 SQL 中用于**分组聚合查询**的核心子句，它们通常一起使用。
##### 3.2.1 GROUP BY
`GROUP BY`字句用来将所有行按某个列值进行分组统计（可以理解为将所有行按组合并为若干个行），与聚合函数结合使用可以统计某一组内的数据：
```sql
select city, count(city), min(temp_lo) from weather
group by city;
-- 按城市分组，查询每个组的计数和观察到的最低温度
```
**`SELECT` 中出现的非聚合列，必须出现在 `GROUP BY` 中**。
##### 3.2.2 HAVING
`HAVING` 对「`GROUP BY`分组后的组」进行过滤。
```sql
-- 查询城市组的计数和观察到的最低温度，前提是这个城市组的所有最低温度都高于0
select city, count(city), min(temp_lo) from weather w
group by city
having min(temp_lo) > 0;
```
**非聚合条件放 `HAVING`是不推荐的做法**
注意不能写成：
```sql
select city, count(city), min(temp_lo) from weather w
group by city
having temp_lo > 0;
-- ❌ 字段 "w.temp_lo" 必须出现在 GROUP BY 子句中或者在聚合函数中使用
```
**`HAVING` 中的每个列，要么是聚合函数（如 `MIN(temp_lo)`），要么必须出现在 `GROUP BY` 中**
#### 3.3 字句执行顺序
`WHERE`和`HAVING`的区别是：`WHERE`在分组和聚集计算之前选取输入行（因此，它控制哪些行进入聚集计算）， 而`HAVING`在分组和聚集之后选取分组行。因此，`WHERE`子句不能包含聚合函数； 相反，`HAVING`子句总是包含聚合函数
**==SQL 子句的逻辑执行顺序是：1. `FROM` → 2. `WHERE` → 3. `GROUP BY` → 4. `HAVING` → 5. `SELECT` → 6. `ORDER BY`==**
```sql
select city, count(city), min(temp_lo) as min from weather w
where temp_lo < 10
group by city
having min(temp_lo) > 0
order by min;
```
